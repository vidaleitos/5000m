# 跨期对照：一年前后同一季节（含方法与分辨率上限）

这是 **年度进步的最诚实的陈述** —— 但它比它看起来脆。这份文件记录怎么做，
以及**什么结论这个方法根本分辨不出来**。

---

## 0. 先确认这次对照真的成立

好的年度对照需要三个条件同时满足，缺一个就不要做：

| 条件 | 判据 |
|---|---|
| 同季节 | 日期相差约 52 周 |
| **露点匹配** | 两期平均露点差 < 1 °C |
| **总量匹配** | 两期周量差 < 5 % |

**实测成立的例子**：

```
2025-W41   86.74 km   平均露点 12.4 °C   最长 22.05 km
2026-W40   85.64 km   平均露点 12.1 °C   最长 16.02 km
```

差 −1.3 %、露点差 0.3 °C。**不需要热修正，不需要配速换算。**

**大部分训练地点一年里只有一两次这样的窗口。** 先扫一遍全史，把能对上的周列出来，
再从里面挑 —— 不要随便挑一周就开始比。

## 1. 软线：心率分档配速

从**逐秒 `record`** 里按 10 bpm 分档累计「秒数」和「米数」，配速 = 总秒 / 总公里。

**不要用会话平均** —— 会话平均把热身、恢复、冷身全搅进去（见主文件 Rule 1）。
逐秒分档能把一堂课内部的分布也保留下来。

```python
def band_pace(path, min_speed=1.4):
    """→ {HR段: [秒数, 米数]}"""
    acc = defaultdict(lambda: [0.0, 0.0])
    for m in fitparse.FitFile(path).get_messages("record"):
        d = {f.name: f.value for f in m}
        hr, sp = d.get("heart_rate"), d.get("enhanced_speed") or d.get("speed")
        if hr is None or sp is None or sp < min_speed:
            continue
        b = (hr // 10) * 10
        acc[b][0] += 1.0        # 秒
        acc[b][1] += sp         # 米
    return {b: list(v) for b, v in acc.items() if v[0] > 30 and v[1] > 50}
```

把两期各自的档加起来，再比同一档的配速。

### ⚠ 这个方法的分辨率上限是 ±10 s/km

实测（同一人，一年前后）：

| HR 段 | 2025 | 2026 | 差 |
|---|---|---|---|
| 120–129 | 5:31.3 | 5:39.4 | **+8.1**（2026 慢）|
| 130–139 | 5:28.3 | 5:33.1 | +4.9 |
| **140–149** | **5:25.3** | **5:23.4** | **−1.9**（2026 快）|
| 150–159 | 5:16.9 | 5:11.4 | −5.5 |
| 160–169 | 4:40.0 | 4:50.6 | **+10.6** |
| 170–179 | 4:11.1 | 4:19.3 | +8.2 |
| 180–189 | 4:04.4 | 4:00.6 | −3.9 |

**符号是乱的。** 相邻档之间从 −5.5 跳到 +10.6。

> **当符号在不同档之间翻转时，正确的结论是「这一年没有可测量的变化」——
> 不是「挑出和我预期一致的那一档」。**

挑一档支持自己先前判断的，是最容易犯、也最难被发现的错误 —— 尤其是运动员已经
听过你说过一次「你的限制在有氧侧」之后。**先写下分辨率上限，再解释表格。**

各档的数据量也要报（本案 140–149 有 2:12:33 vs 1:37:23，是最厚的一段；
110–119 只有 3 分钟，直接不显示）。**数据量和结论的可信度一起说。**

## 2. 硬线：稳态圈的触地（按配速归一化）

**心率这条软线受换传感器污染**（见主文件）。
**触地和步频不依赖心率，也不依赖跨期配速换算** —— 所以它是这个对照里唯一硬的东西。

取两期**主轻松跑的全部连续 1 km 圈**（排除热身/冷身、排除间歇），然后：

1. 直接比平均配速、平均心率、平均触地、平均步频、平均步幅
2. **再折算到同一配速**（对触地–配速做最小二乘，取斜率，外推到参考配速）——
   因为两期的轻松跑配速本来就不同，不归一化就是在比配速不是在比人

```python
def slope330(L):           # L = [{pace, gct}, ...]
    xs = [x["pace"] for x in L]; ys = [x["gct"] for x in L]
    n = len(xs); mx = mean(xs); my = mean(ys)
    b = sum((xs[i]-mx)*(ys[i]-my) for i in range(n)) / sum((xs[i]-mx)**2 for i in range(n))
    return my + b*(330 - mx), b        # 折算到 330 s/km 的触地, 斜率
```

**实测结果**：

| | 圈数 | 配速 | 心率 | 触地 | 步频 | 步幅 |
|---|---|---|---|---|---|---|
| 2025 | 36 | 332.6 | 144 | 242.3 | **191** | 93.73 |
| 2026 | 17 | 343.2 | 125 | 251.4 | **183** | 94.67 |

**折算到 330 s/km：240.3 → 246.0 ms（+5.7 ms，+2.4 %）。**

**步频每一圈都差 8 spm —— 那不是噪声。步幅几乎没变（93.7 → 94.7 cm）。**

### 关键的第二问：这个变化蔓延到快配速了吗？

**一定要再按配速分桶看一遍。** 实测：

| 配速段 | 触地 2025 | 触地 2026 | 差 |
|---|---|---|---|
| 240–249 | 217.6 | 218.7 | +1.0 |
| 250–259 | 221.6 | 219.6 | −2.1 |
| 310–319 | 241.8 | 242.8 | +1.1 |
| **320–329** | 240.4 | 245.8 | **+5.3** |
| **330–339** | 242.4 | 249.4 | **+7.0** |

**快配速上两期一致（±2 ms）；差异只出现在轻松区间。**

**这个区分决定了怎么解读**：触地变长如果只在轻松跑上 → 是「跑得更松」的机械后果，
不是能力下降；如果蔓延到质量配速 → 才是真的退化。
**只看总平均会把这两种情况混为一谈。**

## 3. 必须做的对账：两期总量要和日志对上

**不要手工把活动 ID 映射到日期。** 我手工映射过一次，把一堂 13 km 课漏了 ——
数字看起来合理，直到总和少了 13 km 才暴露。

**规矩**：
1. **露点、日期、距离从日志工作簿读**（它已经是权威口径），不要重新硬编码一张表
2. 脚本里加一条断言：`len(这一期的活动) == len(日志里这一期的活动)`，不等就打印出来
3. 最后打印两期总量，和日志核对

```python
if len(S26) != len(LOG26):
    print("! 2026 期匹配数不符:", len(S26), "vs", len(LOG26))
```

**输出形如**：`2025-W41: 86.74km / 8次  2026-W40: 85.64km / 10次` ——
这两个数字必须和日志的周汇总一致，否则下面所有分析作废。

**同一条规矩适用于旧数据**：日志里的活动 ID 来自汇总 JSON，而 archive 里的 FIT 要靠
「日期 + 距离（保留一位小数）」去匹配。**别按日期单独匹配** —— 一天两练会撞车。

## 4. 交付物：单独一个工作簿

**不要加进日志工作簿。** 日志生成器在「新建」路径上会重建 sheet，分析产物会被一起清掉；
而如果它只追加，这个 sheet 就永远不会刷新。**分析产物是另一个文件。**

```
<Athlete>_同期对照_<A>_vs_<B>.xlsx
  结论              一眼能看完的对照表 + 三条结论 + 边界声明
  逐次课            两期每一次活动，全部字段并排（带「本周」列以便筛选）
  HR段配速          软线表，带数据量列和配速差
  轻松跑机械        硬线表 + 逐圈明细
  触地-配速曲线      按配速分桶，看差异有没有蔓延到快配速
  数据来源与口径    ⚠ 项必须写全：传感器换代、每周样本量、自动初判标签
```

**报告纪律**：
- **先把「方法的分辨率上限」和「结论」并排写出来**，让读的人知道哪些格子不能读
- **传感器换代必须写在结论表里，不是脚注里**（本案：2025 是腕表、2026 是胸带）
- 一句话说清「哪条线是硬的」——本案是触地和步频，不是心率
- 不要把「结构变了」写成「进步了」。结构变化可以是真的、也是你自己推的方向，
  但**它不等于引擎变了**。这两件事在同一张表里必须分开写。

## 5. 年度对照给出「无变化」之后怎么办

**空结果不是死路 —— 它把问题精确定位到了「这一年里真正动过的那一段」。**

本案：年度对照说不出话（§1 的符号是乱的），但**同一份日志**里，
2025-12 → 2026-01 那个区块的 5K 估算从 ~18:33 掉到 ~17:42。
问题于是从「这一年进步了吗」变成 **「那个区块和这两周差在哪」** ——
而它们的周量几乎一样（~80 vs ~86 km）。

差的是硬课的**形态**：那个区块几乎全是**连续跑**，而现在的质量课全分解成组
（`5×6 min` / `4×2000 m` / `5×1000 m`）。而分解本身就会让同样的配速变便宜
（见主文件「恢复段是训练变量」）。

**这是假设，不是结论。** 一个区块 + 两周撑不起因果 —— 写出来的时候要标清楚，
并写出验证窗口（本案：下一个露点 <12 °C 的月份）。

**做法**：
1. 年度对照为 null 时，**下一步不是再堆数据，是在同一份日志里找「变化发生过」的子区间**
2. 用周汇总把「量相近但结果不同」的配对列出来（本案：~80 km/周 的两个时期）
3. 比的是**课的形态**（连续 vs 分解、工作/恢复比），不是量 —— 量已经被配对掉了
4. 明确标注这是待验证假设 + 验证窗口，不要写成结论
