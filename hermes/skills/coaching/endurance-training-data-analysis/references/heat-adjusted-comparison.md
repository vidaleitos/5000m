# 热负荷修正下的跨时期配速比较

**为什么需要这套方法**：任何跨季节的配速比较，如果不控制热负荷，结论会完全相反。
本文件写于一次真实的误判之后 —— 先把 7-8 月的退步归因于"量掉了导致有氧崩了"，
引入真实露点后，一半的结论被推翻。

---

## 1. 手表温度字段不可用

Garmin 的 `temperature` / `minTemperature` / `maxTemperature` 被皮肤温度污染，
**跨季节完全不可比**：

| 月份 | 手表说 | 真实值（气象再分析）|
|---|---|---|
| 2025-12 | 23.6°C | **0.6°C** |
| 2026-01 | 22.4°C | **−1.7°C** |

手表在冬季读高 20+°C。**永远不要用它做任何跨时期比较。**

## 2. 真实气象数据源

Open-Meteo 历史再分析（免费，无需 key）：

```
https://archive-api.open-meteo.com/v1/archive
  ?latitude={lat}&longitude={lon}
  &start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
  &hourly=temperature_2m,relative_humidity_2m,dew_point_2m,apparent_temperature
  &timezone=Asia%2FShanghai
```

坐标从活动记录的 `startLatitude` / `startLongitude` 按月份聚合得到。

**抓取注意：**
- **按月分次抓取**，不要一次拉 14 个月（大请求会 read timeout）。逐月小请求 + 重试 4 次能跑通
- 这个 API 会间歇性报 `SSLEOFError` / `RemoteDisconnected` —— **瞬时错误，重试即可**，不是环境问题
- 缓存到本地 JSON，断了能续；长任务用 `terminal(background=True, notify=True)` 跑
- 匹配逻辑：把课的开始时间取整到小时，**按地点分表**取那一小时的 T / RH / DP

## 3. 三档分析，从强到弱

### ① 露点匹配 + 心率带匹配的直接比较（无模型假设，首选）

把课按露点分箱（例如 −4~2 / 9–11 / 14–17 / 22–24 °C），箱内比平均配速。
**这是唯一不需要假设校正系数的做法。** 只比较落在同一箱里的月份/区块。

### ② 每期回归 pace ~ HR，再在固定 HR 比较

```python
# pace(min/km) = a + b*HR  → 报告 @HR150 的预测配速 + n + R²
```

控制"心率带构成逐月漂移"的问题（同一个配速带，不同时期装的课性质不同）。
**R² 常低到 0.27–0.4** —— 同一时期课的性质会变，所以置信度不要给高。

### ③ 露点归一（最弱，只做旁证）

文献区间 **0.3–0.5 s/km 每 °C 露点**，取 0.41。**必须声明这是模型假设。**

**符号最容易搞反**：从热条件归一到凉条件，配速应该**变快**。
（写成 `p + (5 - dp) * k` 会得到反的结果 —— 检查一遍方向再输出。）

## 4. 稳态课过滤（前提条件）

间歇课的会话平均配速毫无意义。混进任何回归都会静默地把结论拉歪：

```python
steady = [r for r in runs if r["km"] >= 7 and (r["mx"] - r["hr"]) <= 28]
```

反例：一次周三间歇课，会话均配 5:54/km、HR 137，但它包含 8×400 m @3:24。
它会被当成"一堂很轻松的慢跑"混进来。

## 5. 文献阈值：当天属于哪一档

| 清晨露点 | 判定 |
|---|---|
| < 12 °C | 理想。按配速跑 |
| 12–18 °C | 轻微。配速表 **+3~5 s/km** 宽容 |
| 18–21 °C | 明显。质量课改按心率/呼吸，配速只作参考 |
| **> 21 °C** | **严重。不追配速**；硬课挪时段或降级 |
| > 24 °C | 硬课应挪时间或取消；高量不可能 |

**露点优于 heat index** —— heat index 来自静息状态的数据，对跑步不准。

## 6. 已知的坑

- **归一系数会过度工作**：取 0.41 s/km/°C 时冷热两端会被拉得很夸张。
  优先用方法 ①，归一法只用旁证。
- **箱内 n 很小**：某个月的稳态课可能只有 10 次，心率带匹配的对照组只有 2–4 次。
  **必须给置信度**，并且用两条独立路径交叉验证方向是否一致。
- **箱内构成漂移**：同一个"5:00–5:30/km"带，7 月的课和 12 月的课性质不同。
  回归法比直接比带均值更能控制这一点。
- **断点和噪声要区分**：如果**所有方法**都指向同一个月出现台阶式变化，那是真断点，不是噪声。

## 7. 一个完整的判读示例（作为模板）

```
检查项                结论                              置信度
─────────────────────────────────────────────────────────
露点匹配同期比较      同露点下慢 23 s/km，热解释不了      中高
心率带交叉验证        方向一致（HR 135-145: 5:10/5:08 → 5:36）中
年对年同条件          同露点同心率快 24–52 s/km           高
─────────────────────────────────────────────────────────
净结论：峰值在 4–6 月；当前是真实退步，且 7-8 月的低量至少部分是热导致的

未回答：量（67 vs 80 km/周）的效果 —— @HR150 测不出差异，
        但这个指标看不见量积累的东西（毛细血管、每搏输出量、后程抗疲劳）。置信度：低。
```

**最后一行的写法很重要**：明确写出"这个指标覆盖不到的区间"，而不是把一个
"测不出差异"当成"没有效果"。

## 8. 最高价值的一个设计：刻意找一对「匹配周」，而不是逐年做回归

长期追踪里最干净的一次对照不是"这个月 vs 上个月"，而是**隔一年、条件几乎重合的两周**。

筛选条件（按重要性）：
1. **平均露点接近** —— 本案 12.4 vs 12.1 °C（差 0.3）。露点不匹配的话后面都白做
2. **周量接近** —— 86.74 vs 85.64 km（差 1.3%）
3. **同季节** —— 避开训练阶段（基础期 vs 赛前）带来的构成差异

本案就是在一份 87 周的周汇总里扫出来的。**这种周不常见，但一年里通常能找到一对**，
而且它比十二个月的回归干净得多。

- **它能回答**："我这一年到底有没有变强"（在两个时点上）
- **它不能回答**：中间发生了什么。两期之间可能包着峰值区块和一次热崩塌 ——
  所以结论要限定成"在 A 和 B 这两周"，不是"这一年"

### 至少比三条互不依赖的线

只比一条线，结论就被那一条的混淆绑架了：

| 线 | 依赖什么 | 本案结果 |
|---|---|---|
| 逐档心率—配速 | 心率（受腕表→胸带换代污染） | 散布 ±10 s/km、方向乱 → **测不出** |
| 同一配速下的触地与步频 | 同一台手表，不依赖心率 | 触地 +5.7 ms、步频 −8 spm，**方向一致** |
| 周总量与负荷 | 距离 + 心率 | km 相同、TRIMP **低 17%** |

**最后一条是公里数单看看不见的**：同样的周公里数，身体承受的负荷可以差百分之十几。
**"量"不是负荷 —— 别拿 km 当负荷的代理。**
（TRIMP 算法见 `references/session-structure-inference.md` §4。）

**注意每一条线各自的不确定性，不要把它们加在一起当成一个总误差。**
本案的写法：第三条受心率带换代影响，所以降为旁证；第二条是唯一不依赖心率的，
而它和第一条能给出一致的机制解释（轻松跑跑得更松 → 步频降 → 触地变长）。
