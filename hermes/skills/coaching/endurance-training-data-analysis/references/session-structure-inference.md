# 从分圈反推「这堂课是什么」+ 一个可比的负荷量

会话平均配速对间歇课没有意义（这是已知的）。但反过来也不够：
**光有一串逐圈配速，你还是答不出"这堂课到底是什么"，也没法把两堂
看起来配速相同的课比出代价差异。**

这套东西把两件事从 FIT 分圈里算出来、写进持久日志：

1. **结构** —— 工作段是几组、多远、什么配速、组间多久
2. **负荷** —— 一个跨时期可比的量

有了这两列，跨时期比较才有共同语言（见 SKILL.md §2）。

---

## 一、结构识别：一条判别式 + 一道门

FIT 的分圈是设备按自动计圈 / 手动计圈切的，**不是"组"**。一次 5×1000 m 可能被切成
`1000m + 444m` 两圈一组（自动计圈 + 间歇键）。所以不能把圈直接当组。

```
1. 取所有 dist ≥ 20 m 且 t ≥ 3 s 的圈
2. 整堂课平均配速 avg_pace
3. 判定每个圈是不是「工作圈」：
       pace ≤ max(avg_pace × 0.92,  fastest_lap × 1.30)
   两个条件取更宽的那个，各自挡一类错：
      avg×0.92  挡住"热身/冷身/恢复慢跑"
      fastest×1.30  挡住"间歇前一两组本来就更慢"（没热开、起跑慢）
4. 相邻同类圈合并成「块」（所以 1000m+444m 会并成 1444m）
5. 只保留 dist ≥ 20 m 的工作块
```

**然后分三种形态输出：**

| 形态 | 条件 | 输出 |
|---|---|---|
| 连续 | 只有 1 个主工作块（或它比第二大块大 3 倍以上），且 ≥2500 m 或 ≥600 s | `连续 30:00` |
| 收尾 | 同一个门，但工作块小（≥100 m） | `+400m` |
| 间歇 | ≥2 个可比的工作块 | `5×1443m` + 恢复 |

平均工作距离 < 60 m 时（短冲 / 爬坡冲刺）改成按**时间**报：`9×8秒（约32m）` ——
短段上距离是 GPS 噪声，时间才是真的。

---

## 二、必须有的那道门："连续"需要跑得够快

**第一版没有门，热身跑被成片误判。**

热身文件里通常既有"跑"也有"走/停"。走路把 
`avg_pace` 抬得很高，于是普通的 5:42/km 慢跑落在 `avg×0.92` 以下，
被判成一个"连续工作块"。输出是一堆假 `连续 18:18` / `连续 17:07` / `连续 11:21`，
对应的是热身、冷身、和 4 km 轻松跑。

**这类错误特别隐蔽：它不报错，它产生一堆看起来很合理的字符串。**

两道门一起才够：

```
门 1（相对）  工作段整体必须快过整堂课 5%  —— 挡掉"整堂课都是工作段"
门 2（绝对）「连续」块还必须快于 MIN_QUALITY_PACE
```

`MIN_QUALITY_PACE` 是运动员自己轻松跑配速与阈值配速之间的一条底线
（本案 310 s/km，即 5:10/km）。低于它就只是"在跑"，不是一次质量刺激。
**把它做成脚本顶部的一个常数，别埋在逻辑里。**

> 相对门单独不够：只要文件里有走路，`avg_pace` 就会被抬高，什么都过得了。
> 绝对门单独也不够：它拦不住"整堂课都在阈值"的情况。

**间歇形态不需要第 2 道门** —— 交替结构本身就是证据。但需要
`len(work_blocks) ≥ 2`，否则退化成分支错误的"单块"路径。

## 三、验收：拿你已经独立算过的课去对

**不要靠"看起来对"。** 挑 10–12 堂**结构已知**的课（你亲手算过工作总量和配速的那种），
跑一遍检测器，逐条对：

```
10/01  连续 30:00 @4:11.1     独立算：30:10 @4:12.4 连续   ✓
10/03  5×1000m @3:43.1        独立算：5×1000 @3:43.1       ✓
10/07  5×1443m @4:09.6        独立算：7213m / 30:00 @4:09.6 ✓
10/09  4×2000m @4:07.0        独立算：8000m / 32:56 @4:07.0 ✓
10/08晚 +400m @3:10.5          独立算：400m @3:10.5          ✓
10/02  8×100m @3:08.5         加速跑                        ✓
长跑 / 轻松跑 / 所有热身冷身   空白                         ✓
```

**负例（必须为空白）和正例一样重要。** 第一版全部正例都对、负例错了 2/4 ——
如果只测正例就会直接交付。

**并且加一个缓存版本号**（见 `persistent-log-workbook.md` §1c）——
这类算法你会改三五次，每次都要能一键重算。

## 四、负荷量：设备字段经常根本不存在

想加一列"负荷"时，先别假设设备导出里有。**本案实测：**
`training_stress_score` / `activity_training_load` / `intensity_factor` 在新版设备导出的
FIT 里**全是 `None`**；只有旧的一次性汇总 JSON 里有 `activityTrainingLoad`。
结果是 489 行有值、48 行永远空白 —— **一列半空的负荷表比没有更糟。**

**换成自己算的 Banister TRIMP，逐秒积分：**

```
HRr   = (HR − HRrest) / (HRmax − HRrest)
TRIMP = Σ_per_second  HRr × 0.64 × e^(1.92 × HRr) / 60        # 男，b = 1.92

HRrest = 45, HRmax = 198   ← 固定常数，写死在脚本顶部
```

固定常数是刻意的：**要的是跨 537 行同口径，不是每人每时最精确。** 写清楚常量取值，
让"这个数是算出来的"变成一条可复核的记录。

**读不到心率流时回退到会话均值公式**（`dur_min × HRr × 0.64 × e^(1.92·HRr)`），
并在说明页写明有多少行走的是回退路径。

**必须声明的偏差**：TRIMP 是心率派生的，所以它**继承心率的全部问题** ——
尤其是腕表 → 心率带换代（系统偏置 5–10 bpm）和热负荷。跨换代比较时降级为旁证。

### 它换来了什么

同样周公里数（差 1.3%）的两个周：

```
2025-W41   86.74 km   周总 TRIMP 785
2026-W40   85.64 km   周总 TRIMP 653      ← 低 17%
```

**公里数一样，代价不一样。** 这解释了"为什么同量今年不觉得累"。
**这是 km 单看不出来的东西** —— 也是它值得单独一列的理由。

## 五、性能："只读分圈"并不比全读快

`fitparse` 的 `get_messages("lap")` **仍然解析整份文件**，只是在返回时过滤。
所以"分圈 pass"和"全记录 pass"是同一个数量级的开销 —— 别指望它省时间。

537 个文件单线程约 10 分钟；改成 8 进程 `ProcessPoolExecutor` 降到 165 秒。
**算法会改多次，所以并行重算写成一个独立脚本**（`refresh_structs.py`），
不需要每次都重跑整个生成器。

## 六、回到分析：工作/恢复比才是强度变量

有了结构列之后，一条早就该写下来的东西才落得下地：

```
10/07   360 s 工作 / 122 s 恢复  =  2.95
10/09   494 s 工作 / 121 s 恢复  =  4.08
```

**同样"跑 4:07–4:10 的阈值"，这不是同一件事。** 恢复不变、工作段拉长，
每一组开始时乳酸更高、心率没降回来，后面几组越来越接近连续跑。

**判一堂阈值课难不难，先看工作/恢复比，再看配速。只看配速会漏掉一半。**

**推论（曾被忽略、后被运动员指出）**：**恢复段是一个训练变量，不是休息。**
运动员**主动**放慢恢复段会改变工作的边际成本 —— 同样一个配速变得更便宜。
所以：
- 跨课比较时，配速必须**附带恢复条件**才可读
- 恢复浮动时，"维持同一工作配速需要多少恢复"本身就是**适应指标**
- 两种干净的处理：① 固定恢复 → 配速可比；② 让恢复浮动 → 把恢复需求当成绩。**让他选。**
